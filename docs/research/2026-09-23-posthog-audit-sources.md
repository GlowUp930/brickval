# Official sources for a native iOS PostHog journey audit

Researched 2026-09-23. This is documentation guidance, not a finding about the live BrickVal project.

## Funnels and test traffic

- PostHog funnels support step-level and global event-property filters, as well as person/group filters. Person-property filters require identified events and person profiles. For BrickVal, apply the recorded environment, simulator/test, first-run, and replay properties consistently to the relevant steps; verify those properties exist on the events before trusting a production conversion rate. The specific BrickVal property names and coverage require a live-data check. [PostHog funnels](https://posthog.com/docs/product-analytics/funnels.md)
- Steps are sequential by default. A repeated event name in two steps requires two actual occurrences. Check step ordering, conversion window, and whether “first-ever” versus “first matching filters” is selected; “first-ever” can exclude a user whose earliest event fell outside the filters or date range. Hide incomplete periods when reading recent conversion trends. [PostHog funnels](https://posthog.com/docs/product-analytics/funnels.md)
- The iOS SDK automatically captures `Application Installed`, `Application Opened`, and other lifecycle events. SwiftUI automatic screen names may be unclear, so explicit screen events are preferable for stable journey steps. [PostHog iOS SDK usage](https://posthog.com/docs/libraries/ios/usage.md)

## Identity and anonymous merging

- The SDK starts with a locally stored anonymous ID. Calling `identify` with a stable user ID links earlier anonymous events to the identified person; a changed ID without linkage can split funnels and replay history. Inspect a sample person's distinct IDs and `$identify` event to verify the join. [PostHog identifying users](https://posthog.com/docs/product-analytics/identify.md), [identity resolution](https://posthog.com/docs/product-analytics/identity-resolution.md)
- `reset` on iOS resets both the current and anonymous IDs, so audit its timing around logout and first-run events. Server, app, and third-party events need a coordinated ID; raw events retain their original `distinct_id` even after person merging. [PostHog iOS SDK usage](https://posthog.com/docs/libraries/ios/usage.md), [identity resolution](https://posthog.com/docs/product-analytics/identity-resolution.md)

## Replay privacy

- SwiftUI replay requires screenshot mode. PostHog warns screenshots may contain sensitive information; iOS defaults mask text inputs and images, while password inputs are always masked. Review actual screens, including paywall and account flows, for any unmasked sensitive content. [PostHog iOS replay installation](https://posthog.com/docs/session-replay/installation/ios.md), [mobile replay](https://posthog.com/docs/session-replay/mobile.md)
- iOS replay network telemetry records metrics such as speed, size, and response code, not request/response bodies, per the documented setting. Log capture is off by default. The iOS SDK supports `ph-no-capture` through an accessibility label or identifier for elements that must be excluded. [PostHog iOS replay installation](https://posthog.com/docs/session-replay/installation/ios.md), [iOS SDK usage](https://posthog.com/docs/libraries/ios/usage.md)

## Superwall and RevenueCat purchase tracking

- Superwall's optional PostHog integration sends subscription/payment events with an `sw_` prefix. Its iOS delegate and presentation handler expose paywall lifecycle callbacks, so distinguish paywall shown, purchase attempted, purchase succeeded, and entitlement active when comparing custom app events with provider events. Confirm which integrations are actually enabled before treating any event family as complete. [Superwall PostHog integration](https://superwall.com/docs/integrations/posthog), [Superwall delegate](https://superwall.com/docs/ios/sdk-reference/SuperwallDelegate), [presentation handler](https://superwall.com/docs/ios/guides/advanced/using-the-presentation-handler)
- RevenueCat's direct PostHog integration sends server-side subscription events such as initial purchase, trial start/conversion, renewal, and cancellation. It uses the `$posthogUserId` subscriber attribute when set, otherwise the RevenueCat App User ID; mismatched IDs can prevent a purchase from joining the app journey. RevenueCat supports separate production/sandbox PostHog keys, and sandbox events require configuration. [RevenueCat PostHog integration](https://www.revenuecat.com/docs/integrations/third-party-integrations/posthog), [RevenueCat event overview](https://www.revenuecat.com/docs/integrations/integrations)
- PostHog also offers a RevenueCat warehouse source with purchase/subscription webhooks, but its webhook events table does not backfill history. Decide which provider path is the purchase source of truth and check for duplicate counting across Superwall, RevenueCat, and custom app events. This is an audit recommendation inferred from the available integration paths. [PostHog RevenueCat source](https://posthog.com/docs/cdp/sources/revenuecat.md), [Superwall PostHog integration](https://superwall.com/docs/integrations/posthog), [RevenueCat PostHog integration](https://www.revenuecat.com/docs/integrations/third-party-integrations/posthog)

## Event schema governance

- PostHog Data Management can document events with descriptions, owners, and tags, and attach reusable typed property groups with required fields. Event names cannot be changed after creation, so define and review canonical journey names and property meanings before adding more instrumentation. [PostHog schema management](https://posthog.com/docs/product-analytics/schema-management.md)
- For this audit, maintain one event dictionary covering trigger, owner/source, identity state, environment/test marker, schema version, privacy-sensitive fields, and whether the event means intent or confirmed outcome. This is a proposed audit convention, not a PostHog requirement. PostHog's iOS SDK supports custom event properties and recommends consistent event naming. [PostHog iOS SDK usage](https://posthog.com/docs/libraries/ios/usage.md), [schema management](https://posthog.com/docs/product-analytics/schema-management.md)
